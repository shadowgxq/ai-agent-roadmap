## 背景与目标

轻记账面向希望快速记录日常收入和支出的个人用户。用户不需要维护账户、资产或复杂财务模型，只需要在消费后完成一笔记录，并在月底快速回答：钱花在哪里、预算是否接近上限、当月还剩多少钱。

本稿把原始 PRD 转成可被 OpenSpec 直接消费的 UX/UI Baseline，明确页面结构、主要路径、状态、恢复动作、视觉基础和稳定 Scenario ID。它不定义生产代码、路由字符串、组件目录或本地存储实现。

## UX Baseline

### 体验目标

| 目标       | 体验要求                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| 快速记录   | 从账单页进入“记一笔”后，金额、分类、日期和保存动作在一个连续页面内完成。 |
| 清楚复盘   | 月度收入、支出、结余始终位于账单和统计页面的高层级位置。                 |
| 安全修改   | 编辑、删除、改月份和切换收支类型都提供明确的影响反馈及取消路径。         |
| 可恢复     | 失败不清空输入，不用旧数据伪装当前结果，并提供重试或返回操作。           |
| 低认知负担 | 只展示本期固定分类和必要字段，不引入账户、资产、同步等非本期概念。       |

### 设计原则

1. 内容优先：账单和金额是主内容，装饰、动画和视觉层次不能抢占记录入口。
2. 一个主动作：每个页面只有一个主要动作；账单页是“记一笔”，预算页是“设置预算”，表单页是“保存”。
3. 结果可解释：收入、支出、预算状态和错误状态同时使用文字、图标和结构表达，不只依赖颜色。
4. 状态不跳动：加载、筛选、月份切换和底部导航切换保留稳定的主要操作位置。
5. 移动优先：先保证 375px 宽度下的单手操作，再在 768px 和 1024px 以上扩展内容宽度和留白。
6. 可回退：弹窗、抽屉和全屏表单都有明确的关闭、取消或返回路径；未保存内容离开前必须确认。

## 信息架构与全局 UI

### 全局 Shell

- 顶部保留系统安全区；页面滚动内容不被顶部或底部固定区域遮挡。
- 账单、预算、统计使用同一个三项底部导航：`账单`、`预算`、`统计`。每项同时展示 Lucide 图标和文字，当前项有颜色、字重和指示线三重状态。
- “记一笔”不占用底部导航。账单页顶部操作区始终显示 `Plus` 图标和“记一笔”主按钮；首次空状态内再提供一次同样的入口。
- 进入记一笔后使用专注的全屏表单壳层，显示返回按钮和页面标题，不显示底部导航，避免表单提交与主导航竞争。
- 固定底部导航和固定表单操作区必须预留底部安全区与内容 padding，最后一条账单、错误提示和保存按钮不能被遮挡。
- 所有可点击元素使用语义按钮或链接；图标按钮有可访问名称，交互区域至少 `44px`，相邻触控目标至少保留 `8px` 间距。

### 弹窗、抽屉与返回

| 交互对象     | 载体                         | 关闭方式                          | 关闭后状态                               |
| ------------ | ---------------------------- | --------------------------------- | ---------------------------------------- |
| 月份选择     | 移动端底部抽屉；大屏居中弹层 | 选择月份、关闭按钮、遮罩或 Escape | 更新页面月份，禁止未来月份               |
| 账单筛选     | 底部抽屉                     | 应用、重置、关闭                  | 保留已应用筛选；关闭未应用内容不改变列表 |
| 预算设置     | 底部抽屉                     | 保存、取消、关闭                  | 取消不改变原预算；成功回到预算页新状态   |
| 删除确认     | 模态确认框                   | 取消、确认删除                    | 取消保留编辑内容；确认后返回账单页       |
| 放弃更改确认 | 模态确认框                   | 继续编辑、放弃                    | 继续编辑保留草稿；放弃返回来源页面       |

遮罩应隔离前景内容，使用语义的 `dialog`、焦点陷阱和关闭后焦点回归。普通保存不增加二次确认，只有删除和放弃未保存更改使用确认。

## UI/Visual Foundation

### Visual Direction

视觉方向为“安静、可信、纸面感的个人财务工具”：使用现有模板的暖色背景、白色表面、深色文字和克制的青绿色主色。设计检索结果中的落地页、夸张标题、渐变 CTA、玻璃拟态和纯白背景不适用于本产品主界面。

`src/shared/styles/tokens.css` 是长期视觉事实源。本稿只描述语义使用方式，不创建第二份运行时 Token。

| 语义       | 现有 Token                                                  | 用法                                                   |
| ---------- | ----------------------------------------------------------- | ------------------------------------------------------ |
| 页面背景   | `--color-background`                                        | 页面和滚动区域背景，保持内容与表面层次。               |
| 内容表面   | `--color-surface`                                           | 汇总区、表单区、抽屉和确认框；避免卡片套卡片。         |
| 主要文字   | `--color-text`                                              | 标题、金额、账单分类和正文。                           |
| 次要文字   | `--color-muted`                                             | 日期、备注、辅助说明和未选状态。                       |
| 主要操作   | `--color-primary`、`--color-primary-strong`                 | 主按钮、选中导航、焦点和主要链接。                     |
| 收入       | `--color-success` + `Plus` 图标/“收入”文字                  | 不只用绿色区分收入。                                   |
| 支出       | `--color-text` 或 `--color-muted` + `Minus` 图标/“支出”文字 | 普通支出不使用危险红色；避免用户把日常支出误解为错误。 |
| 接近预算   | `--color-warning` + 警示图标/文字                           | 80% 至未满 100%。                                      |
| 达到或超支 | `--color-danger` + 警示图标/文字                            | 100% 及以上；同时显示超出金额。                        |
| 错误和焦点 | `--color-danger`、`--color-focus-ring`                      | 错误说明、输入焦点和可恢复操作。                       |

### 排版、形状与动效

- 使用现有 `--font-family-base`；金额、比例和日期使用等宽数字或 `font-variant-numeric: tabular-nums`，防止切换月份时数字宽度抖动。
- 正文不低于 `16px`；标签和辅助文字使用现有小字号，但不依靠小字承载关键业务信息。标题按页面层级使用 `24px` 左右的紧凑规格，不使用营销型超大标题。
- 沿用现有 `4px/8px` 间距节奏和 `6px/8px` 小圆角；页面区块使用留白和分隔线组织，不使用大量漂浮卡片或嵌套卡片。
- 使用 Lucide 图标，统一线性风格和图标尺寸。禁止使用 emoji 作为导航、状态或操作图标。
- 按下、聚焦、打开抽屉和保存反馈使用 `150-300ms` 的 opacity/transform 过渡；不通过改变布局尺寸制造跳动，并尊重 `prefers-reduced-motion`。

### 统计图表选择

支出分类最多有 7 个固定分类，核心任务是比较金额并找出最高分类。因此统计页使用“按金额降序的水平条形图”作为图表，直接在条旁显示金额和占比；分类列表是精确阅读和屏幕阅读器的完整替代，不把饼图颜色作为唯一信息来源。图表需要提供可读的汇总文本、图例和键盘/触摸可达的分类项。

## 页面结构与交互稿

以下是结构稿，不是像素级视觉稿。OpenSpec `design.md` 应以这些信息为事实源，再结合现有 Token 细化尺寸和组件边界。

### 账单页 `page-ledger`

```text
[本月 2026 年 07 月 v]                         [Plus 记一笔]

[收入 ¥0.00]       [支出 ¥0.00]       [结余 ¥0.00]

[全部] [收入] [支出]       [分类筛选 v] [重置]

07 月 28 日                         收入 ¥0.00  支出 ¥35.50
  餐饮   晚餐                             - ¥35.50

07 月 27 日                         收入 ¥0.00  支出 ¥0.00
  ...

[Receipt 账单]       [Gauge 预算]       [Chart 统计]
```

- 月份选择器展示当前选中月份；前后切换按钮只允许进入已有账单的历史月份或当前月份，未来月份按钮禁用并说明原因。
- 汇总区始终计算所选月份全部账单。筛选变化只刷新明细和日期小计，汇总区保留原金额。
- 日期组按交易日期倒序；组内账单按创建时间倒序。账单行展示分类、备注、日期组内金额和收入/支出标识。
- 首次无任何账单时展示“记第一笔账”空状态；历史月份无账单时说明月份；筛选无结果时保留筛选条件并突出“重置筛选”。
- 账单数据读取失败时，汇总和列表整体进入错误状态，不保留可能过期的金额，只提供“重试”。

### 记一笔页 `page-entry`

```text
[ChevronLeft 返回]              记一笔 / 编辑账单

             [支出] [收入]

金额 *
¥ 0.00

分类 *
[餐饮] [交通] [购物] [居住]
[娱乐] [医疗] [其他]

交易日期 *
[2026-07-28]

备注
[选填，最多 50 个字符]

[保存]
(编辑状态) [Trash2 删除]
```

- 新增默认选择支出、交易日期为本地当前日期；分类不默认选中。编辑状态预填所有字段。
- 金额输入使用数字键盘和人民币前缀；字段标签始终可见，不用 placeholder 替代 label。
- 切换收支类型立即清空原分类，并让分类区域进入“需重新选择”状态；保存按钮保持可见但在分类未选时不可成功提交。
- 日期选择器禁用未来日期；修改日期跨月时，在保存成功反馈中明确“已归入新月份”，返回账单页定位新月份。
- 校验在 blur 与 submit 时运行。错误信息显示在字段下方，提交错误后焦点移到第一个错误字段，其他输入保留。
- 保存 pending 时按钮禁用并显示“保存中”；成功后返回账单页并展示简短成功反馈；失败时留在当前表单，保留全部输入并提供再次保存。
- 删除入口只在编辑状态出现，使用危险语义色并与保存操作分离。确认框明确“删除后无法在产品内恢复”。

### 预算页 `page-budget`

```text
[本月预算]

本月支出
¥0.00

未设置预算
设置预算后可查看剩余额度和使用状态
[设置预算]

[账单]          [预算]          [统计]
```

已设置预算时替换为：

```text
[本月预算]                                      [修改]

预算金额                         ¥1,000.00
已使用                           ¥799.99
剩余                             ¥200.01

[==========------] 80.0%
[AlertCircle] 接近预算

本月支出只计算支出账单，收入不计入使用金额。
```

- 预算页只对应当前自然月，不显示历史月份选择器。新月份展示未设置预算，不复制上月金额。
- 预算设置使用底部抽屉，金额规则与账单金额一致；取消不改变原预算。
- 进度状态必须同时显示文字、比例/金额和图标：正常、接近预算、达到预算上限。超过上限时显示“超出 ¥X”。
- 当前月没有支出时显示已使用 `¥0.00`，仍允许设置或修改预算。
- 预算读取失败时不显示未经确认的进度；保存失败时保留输入和原预算，提供重试。

### 统计页 `page-statistics`

```text
[2026 年 07 月 v]

收入 ¥3,000.00       支出 ¥1,280.00       结余 ¥1,720.00

支出分类
餐饮  ████████████  ¥520.00  40.6%
交通  ██████        ¥260.00  20.3%
购物  ████          ¥180.00  14.1%
其他  ███           ¥120.00   9.4%

分类明细
1  餐饮                         ¥520.00   40.6%
2  交通                         ¥260.00   20.3%
...

[账单]          [预算]          [统计]
```

- 月份选择器与账单页使用一致的月份规则；切换月份后汇总、图表和列表一起更新。
- 汇总区与账单页使用完全相同的收入、支出、结余口径。
- 只有收入没有支出时，保留汇总区，在分类区展示“暂无支出数据”，不渲染空图表。
- 所选月份无任何账单时展示无统计数据空状态，不展示坐标轴或空白图表框。
- 读取失败时展示错误和重试，不用旧月份数据替代当前结果。

## State Matrix

| Surface/State ID                       | 触发                     | UI 呈现                              | 用户可执行动作       | 数据与恢复约束                             |
| -------------------------------------- | ------------------------ | ------------------------------------ | -------------------- | ------------------------------------------ |
| `ledger.loading`                       | 首次读取或切换月份       | 汇总骨架、日期组骨架，主按钮位置不变 | 等待或重试           | 预留稳定高度，不显示未经确认金额。         |
| `ledger.empty.first-use`               | 设备没有任何账单         | 说明首次记录用途，显示 `记第一笔账`  | 进入新增表单         | 不显示虚构的金额和筛选控件结果。           |
| `ledger.empty.month`                   | 历史月份无账单           | 说明当前月份无账单                   | 切回当前月或进入记账 | 月份选择仍可用。                           |
| `ledger.empty.filter`                  | 筛选无匹配               | 保留当前筛选 chip，说明没有匹配账单  | `重置筛选`           | 顶部月度汇总不变。                         |
| `ledger.error`                         | 账单读取失败             | 错误原因概述和重试按钮               | 重试                 | 不展示旧月份汇总。                         |
| `entry.ready.new` / `entry.ready.edit` | 新增或点击账单           | 表单完整可编辑；编辑预填             | 填写、保存、返回     | 类型、分类、日期和备注关系明确。           |
| `entry.validation`                     | blur 或保存校验失败      | 字段下方错误，错误字段聚焦           | 修正字段后重试       | 其他输入和草稿保留。                       |
| `entry.pending`                        | 保存或删除进行中         | 操作按钮 pending/disabled            | 不可重复提交         | 不提前改变列表、预算或统计。               |
| `entry.save-error`                     | 保存失败                 | 表单内错误和再次保存                 | 修改或重试           | 留在表单，保留所有输入。                   |
| `entry.discard-confirm`                | 有未保存更改时返回       | 确认放弃弹窗                         | 继续编辑 / 放弃      | 继续编辑保留草稿；放弃才离开。             |
| `entry.delete-confirm`                 | 编辑状态点击删除         | 不可恢复警告弹窗                     | 取消 / 确认删除      | 取消不改变账单和草稿；确认后同步相关月份。 |
| `budget.unset`                         | 当前月没有预算           | 支出总额、未设置说明、设置入口       | 设置预算             | 不显示虚构剩余金额。                       |
| `budget.normal`                        | 使用比例 `< 80%`         | 进度、剩余金额、正常文字和图标       | 修改预算或去记账     | 支出变化后重新计算。                       |
| `budget.near-limit`                    | `80% <= 使用比例 < 100%` | 警示色、比例、剩余金额和提醒文字     | 修改预算或去记账     | 文字和图标不能只用颜色表达。               |
| `budget.over-limit`                    | `使用比例 >= 100%`       | 风险状态、进度、超出金额             | 修改预算或去记账     | 超支金额明确展示。                         |
| `budget.error`                         | 读取或保存预算失败       | 错误、重试、原预算或输入保留         | 重试或取消           | 不展示未经确认的进度，不部分更新。         |
| `statistics.normal`                    | 目标月份有收支/支出      | 汇总、水平条形图、分类排行           | 切换月份             | 图表和列表口径、颜色一致。                 |
| `statistics.empty`                     | 目标月份没有账单         | 无统计数据说明                       | 切换月份或去记账     | 不展示空坐标轴或旧月份数据。               |
| `statistics.income-only`               | 有收入但无支出           | 保留收支汇总，分类区暂无支出         | 切换月份或去记账     | 不渲染误导性的 0% 图表。                   |
| `statistics.error`                     | 读取统计失败             | 错误说明和重试                       | 重试                 | 不使用其他月份数据替代。                   |

## Form、反馈与可访问性规则

### 字段交互

| 字段     | 默认/输入                        | 校验时机                | 错误与恢复                                   |
| -------- | -------------------------------- | ----------------------- | -------------------------------------------- |
| 金额     | 空值；数字键盘；显示人民币前缀   | blur、submit            | 必填、大于 0、两位小数、上限；错误靠近字段。 |
| 收支类型 | 新增默认支出；编辑预填           | 切换立即生效            | 清空原分类，并让分类重新选择。               |
| 分类     | 无默认值；只显示当前类型固定分类 | submit 或用户离开分类区 | 必填；未选择时阻止保存。                     |
| 交易日期 | 本地当前日期                     | 选择与 submit           | 未来日期不可选并说明原因。                   |
| 备注     | 空值；去除首尾空格               | blur、submit            | 最多 50 个字符；保留原始输入便于修正。       |
| 预算金额 | 空值或原预算                     | blur、submit            | 与账单金额相同的数值规则；失败不覆盖原预算。 |

### 反馈规则

- 动态错误使用 `role="alert"` 或 `aria-live`；toast 使用 `aria-live="polite"` 且不抢焦点。
- 保存、删除和预算修改都有可见 pending 状态；按钮禁用不能是唯一反馈，需保留“保存中/删除中/更新中”等文字。
- 成功反馈不阻塞后续操作，新增/删除以返回账单页为主，预算保存留在预算页显示新进度。
- 错误反馈包含原因和下一步，例如“保存失败，数据未更新。再次保存”或“读取失败，重试”。
- 颜色不作为唯一状态编码；收入/支出、预算风险和错误同时有文字、图标、金额或边框层次。
- 键盘顺序遵循视觉顺序；打开抽屉或弹窗后焦点进入前景，关闭后回到触发控件。

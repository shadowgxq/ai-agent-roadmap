## ADDED Requirements

### Requirement: 本地持久化账单记录

系统 SHALL 在同一设备本地持久化账单记录，并在读取后恢复稳定 ID、交易日期、创建时间、金额、类型、分类和备注。repository MUST 校验版本化存储结构、字段类型、金额范围、日期格式及类型/分类关系；读写错误必须归一化为可供页面展示和重试的错误结果。

#### Scenario: 刷新后恢复记录
- **WHEN** 用户重新打开账单页或刷新应用
- **THEN** 系统从本地存储恢复已保存账单，并按交易日期重新计算当前月份数据，金额和记录字段与保存成功时一致

#### Scenario: 读取失败
- **WHEN** 本地存储读取失败
- **THEN** repository 返回结构化错误，调用方不接收部分或旧数据作为成功结果

#### Scenario: persisted 数据结构无效
- **WHEN** 本地存储中的账单快照缺少必需字段、包含未知类型/分类或无法通过金额/日期校验
- **THEN** repository 返回可恢复的读取错误，不静默清空或部分恢复账单，并提供重试路径

### Requirement: 账单 mutation 原子性和汇总一致性

系统 MUST 将新增、覆盖编辑、跨月编辑和删除视为原子 mutation：成功时持久化结果与派生汇总一致，失败时原记录、草稿外部数据和相关月份汇总保持不变。预算与统计必须能通过同一账单数据源重新计算相关月份。

#### Scenario: 编辑不重复
- **WHEN** 对已有 ID 执行编辑保存
- **THEN** 本地数据只保留一条该 ID 记录，新的字段完整覆盖旧字段，创建时间仍用于同日排序

#### Scenario: 跨月一致性
- **WHEN** 成功保存导致记录从月份 A 迁移到月份 B
- **THEN** 月份 A 和 B 的收入、支出、结余及其消费者读取结果都反映迁移后的数据

#### Scenario: mutation 失败无部分更新
- **WHEN** 新增、编辑或删除的本地写入失败
- **THEN** 记录和所有受影响月份的汇总维持 mutation 前状态，页面提供恢复或重试路径

#### Scenario: 删除成功后持久化一致
- **WHEN** 用户确认删除并且本地写入成功
- **THEN** 目标 ID 从持久化快照中消失，重新打开或刷新后记录仍不存在，相关月份从最新完整集合重新计算

# W20｜生产后端：持久化、异步任务与并发

> **一句话目标**：把 support-agent 从可运行的 graph 升级为可由 API 提交、worker 执行、客户端查询和取消恢复的长任务服务。
> **时间预算**：10–15h，5–6 个 session｜**前置**：W19 RAG 入库与检索 eval 通过。

## 1. 核心要掌握

### API 请求与 Agent 执行解耦

- FastAPI 请求只做鉴权、参数校验、创建 run 和返回 202，不在请求线程执行整个 graph。
- worker 负责加载 graph、设置 thread_id 和发布应用事件。
- run 状态固定为 queued、running、waiting_approval、succeeded、failed、cancelled。
- 终态只能从一个非终态递进到终态；所有状态变更都要有审计记录。

### 幂等、重试、取消与超时

- 使用 Idempotency-Key 防止重复提交；相同 key 和 payload 返回原 run，不同 payload 返回 409。
- LLM 短暂错误可指数退避；业务工具按错误类型决定是否可重试。
- 取消同时写入业务状态和 worker cancellation flag；已完成的外部写入不能假装回滚。
- 超时显式返回 failed + timeout，不把客户端断线当成任务终态。

### 数据库与事务边界

- SQLAlchemy 2 异步 session 只在 repository/service 层使用，不放进 graph state。
- 创建 run 与投递任务要处理“数据库已提交但队列没有收到”的窗口；使用 outbox 或事务后投递加补偿扫描。
- run_events 使用 (run_id, sequence) 唯一约束，SSE 从 Last-Event-ID 续传。

## 3. 落地执行

### Session 1（~2h）：建立业务数据模型

- 建 organizations、users、memberships、tickets、runs、run_events、approvals、tool_actions、audit_events 最小表。
- 用 Alembic 创建 migration，所有 ID 与 timestamp 有明确类型。
- 为 run 状态、event sequence、idempotency key 和 tenant scope 建索引/唯一约束。
- **完成标志**：空数据库可重复执行 migration，不破坏已有数据。

### Session 2（~2h）：FastAPI 分层与 run API

- 实现 POST /api/v1/tickets、POST /api/v1/tickets/{id}/runs、GET /api/v1/runs/{id}。
- route 只处理 DTO；service 负责编排；repository 负责 SQL。
- 错误统一为 code/message/request_id，不把 traceback 返回前端。
- **完成标志**：重复请求不创建重复 run，非法 ID 不泄露其他租户数据。

### Session 3（~2h）：Redis + worker 执行

- 用 Celery 投递 run_agent_task(run_id, thread_id)；worker 中调用 graph，不在 FastAPI request 中长时间运行。
- Redis 只作为 broker/result backend；业务真实状态仍以 PostgreSQL 为准。
- 执行前检查 run 状态和幂等 key，完成后写终态和 done event。
- **完成标志**：API 在 1s 内返回 202，worker 异步完成，不阻塞其他请求。

### Session 4（~2h）：取消、重试与 outbox

- 实现 POST /runs/{id}/cancel，使用数据库状态 + cancellation flag，不强行回滚已完成的外部操作。
- LLM 网络暂时错误重试 2–3 次；业务 tool 只有在确定安全时重试。
- 用 outbox_events 记录待投递任务，补偿扫描定时重投递。
- **完成标志**：worker 重启后，queued run 不会永久卡住。

### Session 5（~2h）：并发与状态机 eval

- 并发提交至少 20 个 run，限制 worker concurrency。
- 验证状态只合法跳转，重复 done 不超过一条，event sequence 无重复。
- 记录 p50/p95 延迟、队列等待、失败率和并发限制。
- **完成标志**：20 个并发 run 无租户串数据、无丢失终态。

### Session 6（P1，~1.5h）：任务队列与模型分流

- 将分类、检索重建和生成分成可观测子任务，但不进行无数量多 Agent 拆分。
- 设计小模型 router，用成本/延迟/eval 数据决定是否保留。

## 6. 常见坑速查

- **FastAPI BackgroundTasks 当队列**：进程或部署重启会丢任务；长任务用 worker。
- **Redis 与 PostgreSQL 两份真相**：定义 PostgreSQL 为业务真相，Redis 只负责传输和调度。
- **重试所有异常**：会重复外部副作用；按错误类型分类。
- **事件只在内存 queue**：重启后无法回放；run_events 必须持久化。

# W22｜现有 React 企业工作台

> **一句话目标**：在仓库已有 frontend/ React SPA 中，完成工单、证据、运行时间线、人工审批、恢复和历史回放闭环，不引入 Next.js。
> **时间预算**：10–15h，5–6 个 session｜**前置**：W21 认证、多租户和安全 eval 通过。

## 1. 核心要掌握

### 现有前端基座已经足够

- frontend/ 使用 Vite + React 18 + TypeScript。
- 已有 src/pages/agent/ 的 AgentPage、useAgentRun、API module 和 RunTimeline。
- 已有 axios、React Router、TanStack Query、Zustand、i18n、theme 和测试基座。
- support route page 只负责 composition、state ownership 和 data flow；API DTO 先转 domain type。

### 事件是唯一事实，UI 状态从事件派生

- 实时流和历史回放都转为同一个 AgentEvent 数组。
- sequence 去重；tool_call/tool_result 用 tool_use_id 配对；done 才是终态。
- SSE 断线重连不覆盖已有事件，不把断流判断成任务失败或完成。
- 不渲染 chain-of-thought；只展示可审计阶段、工具摘要、证据和审批内容。

### 用户业务路径

~~~text
工单列表 → 工单详情 → 启动 run
  → 查看 status/retrieval/text/tool
  → approval_required 时审批
  → approve/reject/revise
  → 恢复并继续看流
  → 查看 done、引用和审计
~~~

## 3. 落地执行

### Session 1（~2h）：设计页面与数据流

- 定义 /support/tickets、/support/tickets/:ticketId、/support/runs/:runId。
- 明确 state owner：列表/详情用 query，活动 run 用 feature hook，审批弹窗用局部状态。
- 固定 DTO 到 domain mapper 与 unknown enum fallback。
- **完成标志**：能画出 request → query/mutation → state → UI 路径。

### Session 2（~2h）：工单列表与详情

- 用 TanStack Query 实现列表、筛选、分页与详情，覆盖加载、空、错误、重试。
- 证据显示 title、heading/page、snippet 和可定位引用。
- 不在组件中拼 URL 或读取 runtime env。
- **完成标志**：刷新后列表/详情与后端一致，筛选不使用旧数据。

### Session 3（~2.5h）：运行时间线与重连

- 扩展 `useAgentRun` 或抽出 `useSupportRun`，在现有 `AgentEvent` 基础上支持 `status/retrieval/text/tool_call/tool_result/context_usage/diff/approval_required/done`。
- reducer 按 sequence 去重，安全处理重复、乱序和未知事件。
- 断线保留 runId 与 cursor，重连后续传，不重置 timeline。
- **完成标志**：手造乱序、重复、缺失 done 流时，UI 不重复渲染并正确显示 transport error。

### Session 4（~2h）：审批与恢复

- approval_required 展示草稿、风险、工具与参数摘要，不展示完整敏感参数。
- approve/reject/revise 使用 mutation，提交中禁止重复操作，以后端状态为准。
- 审批后自动重连；离开页面后返回仍可回放。
- **完成标志**：三种审批结果都有 pending/success/error 状态。

### Session 5（~2h）：历史回放与审计

- 时间线同时支持 live/replay 两个数据源。
- 审计显示 actor、tool、decision、timestamp、correlation ID，敏感字段只显示 redact 版本。
- 长文本和工具错误可折叠，保证大量事件可扫描。
- **完成标志**：任意已完成 run 刷新后可回放，与实时结果一致。

### Session 6（P1，~1.5h）：可访问性和响应式

- 补齐键盘焦点、aria-live、错误重试和移动端时间线。
- 不引入第二套 UI 框架，沿用 shared UI、theme 和 i18n。

## 6. 常见坑速查

- **EventSource 断线就开新 run**：只重连原 run，否则会重复执行和计费。
- **localStorage 保存 token**：使用 HttpOnly cookie + 同源反向代理。
- **组件直接消费 DTO**：先转 domain type，隔离接口变更。
- **展示 chain-of-thought**：只展示可审计阶段和工具摘要。

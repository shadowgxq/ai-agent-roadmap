# W23｜E2E 质量闭环、部署与求职证据

> **一句话目标**：用 30 个端到端 eval、Langfuse trace、并发检查和公开 React demo，把 support-agent 变成可展示、可解释、可面试口述的完整交付物。
> **时间预算**：10–15h，5–6 个 session｜**前置**：W22 React 工作台闭环完成。

## 1. 核心要掌握

### E2E eval 覆盖业务路径

30 个 case 固定分配：

- 8 个分类/澄清。
- 8 个检索/引用/无答案。
- 5 个低风险自动回复。
- 4 个高风险审批。
- 3 个恢复/重试/幂等。
- 2 个跨租户和 prompt injection。

能用命令或状态断言评估的不用 LLM judge；只对回复完整性、措辞和解释质量使用 judge，并人工抽查。

### 可观测指标

每次 run 至少记录：脱敏 tenant 标识、run/thread/ticket ID、路由、节点调用、token、成本、延迟、重试、审批等待和终态。

- 不记录密钥、cookie、完整 PII 和完整隐私工具参数。
- trace 用于调试与评估，run_events 用于前端回放。
- 失败 tags 固定为 clarification、retrieval、grounding、approval、tool、infra、security。

### 小规模可复现部署

- frontend/ 构建为 Vite 静态产物，通过 VITE_API_BASE_URL 配置后端。
- support-agent + PostgreSQL + Redis + worker 使用 Docker Compose，不学习 Kubernetes。
- 优先使用同源 /api/v1 反向代理，保留 HttpOnly cookie 和 EventSource。
- 公开 demo 只用预置 fixture 和模拟 CRM，不开放任意 shell 或真实企业数据。

## 3. 落地执行

### Session 1（~2h）：E2E eval runner

- 使用工单 fixture 和固定知识库，每次在独立或重置的测试数据上运行。
- 报告路径、终态、证据、审批、工具次数、成本和延迟。
- 相同 case 可重跑，不混入上次 checkpoint 或事件。
- **完成标志**：一条命令运行 30 个 case 并输出汇总。

### Session 2（~2h）：Langfuse trace 与 score

- graph node、LLM、retrieval、tool action、approval wait 挂到同一 run trace。
- 上报 token、cost、latency、case_id、experiment 和失败分类，先做脱敏。
- Recall@5、citation correctness、E2E success 作为 score。
- **完成标志**：能从失败 trace 定位到具体环节。

### Session 3（~2h）：并发、故障与安全回归

- 为 case 加超时、重试、跨租户和审批不可绕过断言。
- 运行至少 20 个并发 run，检查事件和数据一致性。
- 注入 DB 断开、Redis 重启、worker 崩溃、LLM timeout、恶意 MCP 返回。
- **完成标志**：无永久 queued、无限重试、重复副作用和数据串租户。

### Session 4（~2h）：成本、延迟与质量优化

- 每轮只改一个变量：top-k、prompt、model router、重试或证据格式。
- 同时比较 success、Recall@5、citation correctness、平均 cost、p95 latency。
- 保留至少 2 条正向可归因实验和 1 条负向实验。
- **完成标志**：evals/LOG.md 中结论可由数据复核。

### Session 5（~2h）：部署与运行手册

- Docker Compose 启动 API、worker、PostgreSQL、Redis，配置 health check 和 migration。
- 公共 demo 使用低权限账号、模拟 CRM、单任务配额与日预算。
- 运行手册覆盖启动、查健、查队列、重试失败 run、回滚与清理。
- **完成标志**：从干净环境按 README 可复现启动。

### Session 6（~2h）：求职证据包

- agent-mini 和 support-agent 各写 3 条带真实数字的简历描述。
- 准备 15 分钟口述：选型、state、RAG、interrupt、幂等、多租户和故障。
- 精读 3 个 JD、更新技能矩阵、投递 5 个高匹配岗位。
- **完成标志**：能脱稿讲清一次故障和两个框架取舍。

## 5. 验收 checklist

- [ ] 30 个 E2E case 可一键运行，覆盖业务、RAG、审批、恢复、安全和并发。
- [ ] Langfuse 可查看 graph/LLM/retrieval/tool/approval 完整 trace。
- [ ] 至少 20 个并发 run 无丢失终态、数据混用或重复副作用。
- [ ] Docker Compose 可从干净环境启动，有 health check 和运行手册。
- [ ] README 有架构图、契约、eval 数据、安全边界、演示 URL 和运行方式。
- [ ] 简历、技能矩阵、项目口述与投递记录就位。

## 6. 常见坑速查

- **只记录成功率提升**：同时报告成本、延迟、安全和检索指标。
- **只在本机启动**：固定 migration、seed、worker 和 health check 顺序。
- **把 Langfuse 当业务状态库**：PostgreSQL 保存业务状态，Langfuse 只观测。
- **只展示漂亮前端**：README 和口述必须覆盖恢复、超时、租户和安全。
